# Delegation Selection

Read this reference only when a managed loop will delegate implementation, specialist assessment, or review work. It applies to native and external agents; the external-provider reference adds its separate consent and sandbox rules.

## Decision ownership

Keep business behavior, UX direction, architecture or public-contract choices, accepted risk, and unresolved ambiguity with the human or orchestrator. Delegation never expands authority or lets a child reinterpret those decisions.

## Delegation gate

Delegate only separable work whose benefit exceeds packet, coordination, and integration cost. Keep the work with the orchestrator when scope overlaps, hidden context is material, or an objective result cannot be independently verified.

## Task packet

Give every child a compact self-contained packet containing the goal or symptom, accepted decisions, bounded read and write scope, relevant acceptance IDs, required proof, escalation conditions, and forbidden actions. Do not require conversation history to execute it.

## Agent selection

Select eligible agents by enforceable capabilities, ambiguity, risk, separability, proof quality, and coordination cost rather than provider or model prestige. When the host exposes comparable cost or speed, prefer the lowest-cost eligible option that preserves the contract and user constraints. Native remains the default; external execution still requires its explicit per-run consent.
